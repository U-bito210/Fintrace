## 一、问题定义

金融投研问答系统当前最普遍的失效方式，不是"答不出来"，而是**把四种性质完全不同的东西混成一段流畅的文字**：

1. 模型参数里的记忆（可能过时、可能凭空生成）；
2. 外部数据源的真实披露（有来源、有时间点、有统计口径）；
3. 由披露推导的计算结果（同比、TTM、估值倍数——需要精确算术）；
4. 分析师的推论与观点（本不该以事实口吻出现）。

一段把 FY 数据说成 TTM、把母公司口径当合并口径、把 611 倍的量级错误写成"约 3.1 亿元"的回答，在文本层面与正确答案毫无区别。人工复核一条这样的结论，需要打开原始披露、定位报表行、核对单位与期间、重算公式——这正是投研工作中成本最高、最容易漏的环节。

**我们的判断**：投研智能体的价值不在于生成更流畅的叙述，而在于**让错误可被发现、让正确可被证明**。因此 FinTrace-CN 从架构上就把上述四类内容隔离开，并且把"拒绝输出"设计成与"输出结论"同等重要的一等结果。

## 三、系统架构：四权分离

系统的核心设计约束是一句话：**LLM 不拥有数据源选择权、财务计算权、证据创建权和 Validator 放行权。**

```
研究问题
  ↓
A 股代码与名称标准化（沪 / 深 / 北）
  ↓
Provider 层：版本化快照 / 在线 Tushare·AkShare
  · 来源、抓取时间、research_as_of 与 available_at 双时点
  · RAW 价格、币种、单位、报告期间全部显式登记
  ↓
结构化研究工具（20 个，统一 status: ok|error 信封）
  ↓
ResearchState + Evidence Ledger（事实 / 计算 / 依赖三类证据）
  ↓
确定性 Python 计算引擎
  · 累计报表 → 单季度 → TTM
  · 同比 / 环比、盈利状态迁移五分支
  · PE / PB / PS、IQR 离群剔除、敏感性矩阵
  ↓
Validator 闸门（financial / report / research 三级）
  ↓ 通过或非阻断警告        ↓ 关键错误
报告 / 工作台 / API 输出    拒绝结论 + 修复提示
```

四层职责边界：

| 层 | 负责 | 明确不负责 |
|---|---|---|
| **Provider** | 提供带来源、时点、口径的事实 | 不做任何推导 |
| **确定性引擎** | 全部财务算术 | 不选择数据源、不写叙述 |
| **Evidence Ledger** | 记录事实、公式、依赖关系与文档定位 | 不判定对错 |
| **LLM Agent** | 理解任务、规划步骤、选择工具、组织叙述 | 不造数据、不算数、不放行结论 |
| **Validator** | 决定结论是否允许输出 | 不生产内容 |

Agent 执行受界：**单轮最多 6 步工具调用、绑定单一快照版本**；支持追问（同一快照内最多 5 轮），但**每一轮都是独立 run**——上一轮结论只作为指代上下文重放，数字必须由本轮工具重新取证，否则 Validator 判 `no_evidence` 并阻断。这条约束的存在，是为了防止"把上一次算的数当作本轮已核实"这一类隐蔽泄漏。

## 四、核心任务与实机结果

### 4.1 财务报告分析

- 财报累计数 → 单季度 → TTM 的确定性转换，全部封闭算例通过；
- 同比统一为 `(cur − prev) / abs(prev)`，并对负基数做保护；
- 盈利状态迁移分五分支（正常 / 扭亏为盈 / 由盈转亏 / 亏损扩大 / 亏损收窄），零基期禁止输出百分比；
- 会计口径变化识别：非经常性损益、重述与前期差错更正、会计估计变更、重分类等六类信号，每条信号强制绑定证据；命中不可比条件时**阻断同比**而非给出一个误导性百分比。

### 4.2 研究报告纠错核查（主展示）

核查器为**纯确定性实现，源码层面禁止引入任何 LLM 依赖**（有专门测试扫描源码文本，含"函数体内延迟 import"用例）。LLM 只承担一件事：把自然语言句子结构化为待核查主张，并保留逐字原句。

覆盖 13 类错误：数值、单位、期间、统计口径、计算、估值倍数、缺失引用、错误引用、无支撑引用、错误页码、过期引用、重述后沿用旧值、无证据因果断言。

**真实材料实机结果**（本项目自建受控语料，非合成占位数据）：

| 项目 | 结果 |
|---|---|
| 参考披露 | 某 A 股上市公司 2024 年年度报告全文，**229 页真实 PDF** |
| 待核查材料 | 人为撰写并植入错误的研究草稿，登记 8 处 |
| 植入错误检出 | **8 / 8 全部检出** |
| 全部检出条数 | 16 条 = 8 处植入 + 8 处连带真检出 |
| 误报 | **0 条**（8 处连带项已逐条判定为真检出） |
| 证据回跳 | 14 条可回跳年报正文页；2 条按设计无事实库证据，回跳草稿页 |

其中两处细节值得说明，因为它们体现的是设计而非巧合：

- **同一句话的两个缺陷互不遮蔽**：草稿第 6 节一句话同时犯"把母公司口径当合并口径"和"同比算错（声明 −14%，按披露复算 −9.70%）"，系统分别报出 `scope_error` 与 `calculation_error`。规则要求任一缺陷都不得关闭另一条检出。
- **"查过没问题"与"没查"必须区分**：估值倍数类错误有两条互不依赖的判定依据（按披露复算 / 声明行业与目标公司行业不符）。coverage 报告按分支分别记录 `ran` 与 `reason`，避免"复算缺股价"被误读成"行业分支也没跑"。

**诚实性限定**：上述草稿由本团队自建，植入项与未引用句子的真值**由构造已知**，因此"误报 0"是在这份受控材料上的结论，**不等于在任意真实研报语料上的误报率**。后者需要公开研报语料与人工标注，本项目已建立采集脚本、目录隔离纪律与标注规范（含"什么情况下不标注"七条），但真实语料尚未采集完成，相关指标在评测报告中如实标注为 `N/A`，不造数。

### 4.3 估值与适用性边界

- PE / PB / PS 同行估值，可比公司按申万一级行业**确定性选取**（同一套行业映射冻结于快照日期）；
- 倍数分布采用 IQR 剔除异常值，且**分方法分别展示 + 报告离散度**，不合成一个虚假的"综合目标价区间"；
- 市值与同行估值一律使用 **RAW 价格**，不复权；
- 方法适用性硬编码为校验规则：对银行等金融机构，不输出 PS、EV/EBITDA 或通用 DCF 结论；
- Bear / Base / Bull 情景 + 敏感性矩阵（PE×EPS、PB×BPS），全部假设入注册表可追溯；矩阵单调性有测试保护。

### 4.4 结论护照与审计回放

- 关键结论生成 **Financial Claim Passport**：一条结论对应一份可独立验证的凭证，`verify_claim()` 返回五态之一——`VERIFIED` / `DEGRADED` / `STALE` / `BLOCKED` / `CONFLICTED`；
- **Audit Replay**：11 阶段时间线（文件加载 → 哈希 → 解析 → 抽取 → 归一化 → 检索 → 工具调用 → 计算 → 主张 → 校验 → 报告），每步含输入、输出、来源、状态与时间戳；**未记录的步骤显式标注 `not_recorded` 而非省略**；
- Run Manifest 记录模型标识、Prompt 组合哈希、快照 ID、Git commit、温度与最大步数，使同输入同配置的复现可被机械校验。

## 六、评测体系

评测原则：**事实、公式与证据使用确定性断言；模型文案不作为金融正确性的裁判。**

五个测试层级：单元测试 → Provider 契约 → Golden 回归 → Agent 评测 → Integration（仅在显式提供凭据时运行）。

**四组 Agent 消融**，用于分离每一层机制的边际贡献：

| 变体 | 工具 | 证据 | Validator |
|---|---|---|---|
| `direct_llm` | ✗ |  | ✗ |
| `agent_tools` | ✓ | 剥离 | ✗ |
| `agent_tools_evidence` | ✓ | ✓ | ✗ |
| `agent_tools_evidence_validator` | ✓ | ✓ | ✓ |

固定指标：工具选择 F1、参数正确率、证据覆盖率、端到端成功率、Validator 拦截率、错误结论泄漏、延迟与成本。每个指标由固定案例与明确分母计算。

**当前回归基线**：离线测试套件 **1753 项通过 / 0 失败**（3 项 integration 已 deselect），不依赖网络、密钥、本地缓存或墙钟时间。

**成本口径的诚实处理**：部分国产模型服务按人民币计费而本系统成本账本以美元记，且同一模型 ID 的单价在多个官方页面之间不一致。因此这些模型登记为"未定价"——成本字段保留但 `cost_currency` 为 `null`，界面显示"未定价（币种未知）"，且**预算闸门与未定价模型不可同时使用**（否则上限永不触发，形同失效），运行时直接拒绝启动。这是 fail-closed 原则在评测元数据上的一致应用。

## 七、创新点

1. **四权分离的架构约束**：LLM 不拥有数据源选择权、计算权、证据创建权与放行权，且这一约束由测试机械守护（核查器源码禁止 import 任何模型客户端）。
2. **拒绝输出是一等公民**：Validator 在证据不足、时点错误、口径混用或方法不适用时阻断结论并给出修复提示，而不是降级为"看起来合理"的文本。系统不只证明"正确的时候能跑"，更证明"**错误的时候知道自己不能下结论**"。
3. **结论护照与五态验证**：把一条投研结论连同其证据依赖打包为可独立复核的凭证，第三方无需信任本系统即可重放验证，并区分已验证 / 降级 / 过期 / 阻断 / 冲突五种状态。
4. **会计约束驱动的错误检测**：以会计恒等式、表格结构、期间关系、跨期与跨源一致性等约束族作为检测面，异常不仅被报告，还被定位到原文页与表格坐标。
5. **对抗性语义评测**：在评测层对财务材料做定向扰动，按错误类型分别统计检出率与误报率，用于回答"覆盖率是多少、误报控制得怎样"这类必须用数字回答的问题。

## 八、已知局限

我们清楚哪些没做、哪些做不到，并认为如实列出比含糊带过更符合本竞赛的价值取向：

1. **不含 DCF**：当前估值主线为相对估值与敏感性分析。现金流折现在方法论上要求显式披露预测假设与终值口径，我们不在初赛提交一个假设来源不可核的折现模型，已列入决赛增强项。
2. **真实研报语料尚未采集**：纠错指标目前在自建受控材料与合成植入集上产出；公开研报语料受版权与授权限制，采集脚本与标注规范已就绪，材料未采集，相关指标如实标注 `N/A`。
3. **格式混杂的表格单元格不自动取数**：解析器仅接受“整个单元格均为数值”（可带明确币种或单位）；年份表头、电话、日期和含数字散文不会进入财务计算，而是进入“无法核验/待人工复核”。这一保守策略降低误取数风险，但不把未提取内容表述为“核验通过”。
4. **每股收益类声明不校验数值**：归一化字典未登记 EPS 指标，草稿中的 EPS 数值只能被要求"给出出处"，不能被判定对错。
5. **单机演示规模**：本地 JSON 任务与线程池适合单机演示，不是多实例生产任务队列。
6. **不接交易**：系统不执行交易、不连接券商账户、不提供个性化投资建议；所有输出为研究辅助，不构成投资建议。

## 九、复现说明

```bash
git clone <仓库地址> && cd FinTrace-CN
python -m venv .venv
# Windows: .venv\Scripts\Activate.ps1    |    macOS/Linux: source .venv/bin/activate
python -m pip install -r requirements.txt
python scripts/bootstrap_demo.py
python -m streamlit run workbench.py        # 研究工作台
```

验证：

```bash
python -m pytest -q -m "not integration" -p no:cacheprovider   # 预期 1753 passed
python scripts/smoke_workbench.py                              # 预期 N/N pages clean
python scripts/rehearse_demo.py --step 6+7                     # 预期 植入 8 处全部检出
```

容器化：`docker compose up` 提供等价环境。默认演示与默认测试**全程离线**，不需要任何 API 密钥。

> Windows 用户注意：默认测试会在仓库忽略的 `tmp/` 中为每次运行创建独立临时目录，避免历史进程留下的 ACL 阻断 fixture 装配；如评审方需指定路径，仍可显式传入 `--basetemp=<目录>`。
